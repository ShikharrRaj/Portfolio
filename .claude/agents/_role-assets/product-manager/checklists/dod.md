# Product Manager — Definition of Done (WF-06 self-check)

Run before returning the Output Contract. Not done until every box is checked or flagged in OPEN.

## PRD.approved.md
- [ ] Problem statement ties to a user need AND a business outcome.
- [ ] Target users/personas are named and bounded.
- [ ] Every goal has a measurable success metric with a baseline and a target.
- [ ] Every requirement is a user outcome (not a technology/mechanism — FM-1).
- [ ] Every requirement has testable acceptance criteria, incl. empty/error/edge states (per UI-03).
- [ ] Requirements are prioritized (MoSCoW or equivalent).
- [ ] Non-goals / out-of-scope are explicit.
- [ ] Constraints & assumptions are listed (incl. any UI-*/AI-* product constraints, by ID).
- [ ] Open-questions log is driven to ZERO before marking "approved".
- [ ] No requirement depends on an unmade product decision (no hidden fork — FM-4).

## Process / boundaries
- [ ] I did not choose tech/architecture (staff-architect) or design screens/flows (uiux-lead).
- [ ] Product forks were decided or escalated to the CEO with a recommendation (not dumped on eng).
- [ ] Standards cited by rule ID only; nothing inlined (EF-01).
- [ ] Output Contract returned with real ARTIFACTS path (`projects/<p>/prd/PRD.approved.md`).
